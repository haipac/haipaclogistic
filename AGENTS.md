## HAIPAC project instructions

- Read `.github/DEPLOYMENT_GUIDE.md` before any publication, Firebase configuration or change to an ecosystem integration.
- Current production architecture is static HTML/CSS/JavaScript on Firebase Hosting with project `haipac-7e19d` providing Auth, Firestore, Storage and Cloud Functions. On 2026-11-21 the owner requested moving the frontend away from Firebase Hosting to GitHub Pages while retaining Firebase Cloud Functions and the rest of the Firebase backend. GitHub's official policy says Pages is not intended or allowed as free hosting for an online business/commercial SaaS. Pro enables Pages for private repositories but the documentation does not state a commercial-use exception; get written guidance from GitHub Support before publishing HAIPAC there. Until eligibility is resolved and the cutover verified, keep the current production site and DNS in place. See `docs/IMPLEMENTATION_PLAN.md` and `.github/DEPLOYMENT_GUIDE.md` for the migration plan.
- Static frontend source lives in `site/`; `npm run build` packages it to `dist/`. The API source lives in `functions/` and builds into the `haipac-api` Firebase codebase. The email scheduler is built from `functions/src/email-index.ts` into the separate `email-functions/` `haipac-email` codebase. Hosting rewrites `/api/**` to function `api` in `us-east4`.
- Never use Smart Cut’s Firebase project for HAIPAC data. Use emulators for local backend work and target production explicitly only for an approved deployment.
- Never add secrets or real credentials to code, docs, examples, logs or client bundles. `.env.example` contains names and safe defaults only.
- Keep Firestore/Storage browser rules deny-by-default. Authorize each server API close to the data it accesses.
- No production price is hardcoded. A full, owner-approved versioned rate card and active coverage are required before quotes can succeed.
- Preserve idempotency for signed Smart Cut callbacks and record auditable admin/operations changes.
- The manual beta workflow publishes the static site and only the `haipac-api` codebase to the Firebase Hosting site `haipac-7e19d`. That same Hosting site serves `haipac-7e19d.web.app` and the attached custom domains `www.haipaclogistics.com` and `haipaclogistics.com`; a beta deploy therefore updates the custom-domain website too. Squarespace remains the domain registrar/DNS provider, and its existing mail records must be preserved. The workflow requires the five API secrets, not the Resend key, and must leave email delivery, legal approval and operations readiness disabled.
- The full release workflow requires all production secrets and a verified HAIPAC sender address. Do not enable quotes, reservations, shipments or customer email until the approved tariff, coverage, legal text, operational procedures and provider setup are ready.
- Do not claim production completion without verifying the frontend host's deployed release/SHA and public domain, the Firebase Functions deployment and project, workflow status, HTTPS, routes, API/CORS and Auth flows. While Firebase Hosting is the active host, verify its release too; after a completed migration, verify that Hosting is no longer in the serving path without removing Firebase backend services.
